## 项目经历

### 企业知识库 RAG 检索与问答平台 · 个人项目　｜　2026.07 – 至今　｜　独立开发

**技术栈**：NestJS / TypeScript、PostgreSQL + pgvector、Elasticsearch、Neo4j、Redis、Mem0、MinIO、Docker Compose

面向多格式文档（PDF / Office）的企业知识库问答：文档入库后由 Agent 自主决定是否检索、检索哪一路，并在回答中给出可核对的内容来源。

- **检索设计为三路互补而非单路**：向量检索负责语义近似，关键词检索负责专有名词与代码类精确命中，图谱检索负责多跳关系问题；前两路并行执行、按排名融合去重，任一路失败时自动降级，不阻塞回答。
- **切分按文档结构而非固定窗口**：将文档解析为标题 / 段落 / 表格 / 代码块等结构，按标题层级聚合后再按长度上限合并，保留章节路径与页码，使回答能定位到原文位置。
- **记忆分层，写入由分类器判定**：短期会话缓存、会话级记忆、用户长期记忆三层分离；由 LLM 判断一轮对话是否值得记忆及该记入哪一层，避免上下文无限膨胀。
- **权限在检索阶段生效**：文档白名单直接下推到向量查询与全文查询的过滤条件，而不是生成后再裁剪。
- **流式链路完整**：Agent 事件流转换为前端消息流后分流为两路——一路 SSE 推给前端，一路累计用于落库，避免"流式输出"与"消息持久化"互相阻塞。

> **边界**：检索侧只做单机部署，未做并发压测，因此不提供 P95 类指标；文档权限做到文档级，未下沉到字段级。

### 数据分析 Agent · 个人项目　｜　2026.06 – 2026.08　｜　独立开发

**技术栈**：Python、FastAPI、LangGraph、Docker SDK、ChromaDB、SQLite、SSE

用户上传数据集后用中文提问，Agent 自主拆解分析步骤，在隔离环境中执行计算并产出图表与结论。

- **用状态机而非单次大模型调用组织任务**：理解 → 规划 → 工具执行 → 观察 → 反思 → 答复，反思节点自主判断"继续 / 重试 / 重新规划"，把多步分析过程变成可观测、可中断的流程。
- **工具按风险分级**：数据集计算、只读 SQL 查询、图表生成、报告保存四类工具；写文件类操作在执行前中断，等待人工确认后续跑。
- **不可信代码双层防护**：静态扫描阶段做语法树作用域追踪，识别别名、反射、魔法属性等绕过常规黑名单的写法；运行阶段用断网、只读文件系统、资源上限的容器兜底——静态扫描负责快速拒绝，容器负责最坏情况。
- **防死循环**：除单步重试上限外，另设工具调用总次数硬上限与空转检测，避免"一直思考不收敛"。
- **记忆双轨**：会话状态用检查点持久化以支持中断续跑；历史分析入向量库，在理解阶段召回作为上下文。

> **边界**：静态扫描无法覆盖编码混淆类绕过，真实防护依赖容器层；当前为单机单实例。

### 多智能体内容生产流水线 · 个人项目　｜　2026.05 – 2026.08　｜　独立开发

**技术栈**：Python、CrewAI、FastAPI、Nginx、systemd、DeepEval

把"一个主题 → 一篇成稿"拆成策划、撰写、校对三个角色顺序协作，并配套交付所需的限流、历史与后台。

- **多 Agent 采用顺序流水线而非自由对话**：角色职责与交接物固定（策划案 → 初稿 → 终稿），把多 Agent 的不确定性收敛在"每段由谁负责"，避免角色互相抢话导致上下文失控。
- **异步任务模型**：提交即返回任务号，前端轮询获取阶段进度与阶段性产出，长任务不占请求连接；页面刷新后可恢复进行中的任务。
- **交付必需的外部性处理**：按来源 IP 做每日额度与白名单、历史记录隔离（非本人不可读）、管理员统计后台，以及 Nginx + systemd 的部署脚本。
- **建立 LLM-as-judge 评测**：按主题相关性、结构、文风匹配、信息量、语言质量五维批量打分并输出理由，作为改动前后的对比基线。
- **由评测定位问题**：首轮评测发现模型在输入信息过少时自行补全不存在的上下文，据此收敛输入约束与提示结构。

> **边界**：单次生成需 1–3 分钟，依赖外部模型服务；进行中任务状态在内存，进程重启会丢失进度（终稿已落盘）。
