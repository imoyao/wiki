## 三、项目成果

**贯穿四个项目的一条主线**：连接器层（人先声明完整，平台照着执行）→ 知识库问答（模型第一次自己决定「查什么」）→ 数据分析 Agent（模型自己决定「怎么做」，于是需要沙箱与人审）→ 账本精灵（把前三个的能力收成一个人能验证的成品）。变的只有调用方——从「用户画的流程图」到「模型的决策」；工具的参数契约、失败补偿与权限边界一路没变。

### 项目一｜账本精灵：投资记账 + 基金研究 Agent　`2026`　个人开源 · 仓库可查 · MCP 端点可直接调用

**技术栈**：Python / Flask / SQLAlchemy / Vue 3 / MCP（stdio 服务端 + Streamable HTTP 客户端）/ pytest / GitHub Actions

**一句话**：把「记账数据查询」与「基金研究」做成可被任意 Agent 调用的工具服务——金融数值一律由确定性代码计算，模型只负责选工具与组织表达。

- **工具契约**：9 个只读工具的 schema + 逐字段校验（类型 / 枚举 / 正则 / 数组递归）；业务约束写进描述（出处强制标注、百分比与小数口径区分、取数失败标「未取到」不补全）——**工具描述就是 prompt**。
- **不信任模型的两条红线**：归属字段（家庭 / 账户）不进参数通道，由鉴权上下文覆盖；用户私有数据强制用户级 Token，缺失即失败、**不回退系统 Token**。
- **协议双向**：同一份工具定义两个方向——服务端走 stdio 对外 9 个只读工具（与内置循环共用一份 schema）；客户端手写 Streamable HTTP 接入 2 家数据服务 9 个工具，会话复用、失效重握、SSE 分流解析（防无 charset 被猜成 Latin-1 折断汉字）、8 类错误分类、数据分级 Token 路由、调用审计收敛一处；另经客户端配置接入基金数据工具面 28 个，用于晨星评级口径交叉核验。
- **分层记忆**：滚动摘要（≤3000 字）+ 最近 3 轮原文 + 关键信息卡（≤800 字，整体替换、不进摘要）；双门槛触发（>6 轮且 >8 条），压缩失败降级到 12 条硬上限。**先保证有界，再谈压缩质量**——纯截断会表现为反复追问同一件事，纯摘要丢最近细节。
- **评估集与归因**：45 条回归集（20 基础 / 2 跨工具 / 8 对抗 / 12 归因·基准·行为 / 3 混淆），24 条已实跑全绿。工具 6→9 后出现选错，根因不是模型退化而是**老工具缺排他边界句**，补齐「何时用 / 何时不用」后 basic 组 20/20——**工具变多放大的正是旧描述的模糊性**。
- **规模与可观测**：3569 次提交 / 358 个测试文件 / 401 个后端模块；每次工具调用落库（入参 / 出参 / 耗时 / 错误码 / token，敏感参数脱敏），失败链路可按会话回放到具体一步。

### 项目二｜数据分析 Agent：自然语言 → 自动分析　`2025.06 – 至今`　企业交付

**技术栈**：Python / FastAPI / LangGraph / SQLite（检查点）/ Docker / ChromaDB

**一句话**：业务人员上传表格用自然语言提问，Agent 先出计划、再逐步写代码在容器里跑，每一步推给前端看；写文件必须等人确认。

- **让走向成为可读的边**：7 节点图（理解 / 计划 / 执行 / 观察 / 反思 / 审批 / 汇总）+ 3 处条件分派，观察节点单点 5 个出口；步骤索引、重试上限、待审批动作全放状态，节点只产出、边做决策；工具调用累计 10 次硬上限兜底，任何分支组合都不会原地空转。
- **AST 扫描用符号表，不用关键字**：执行前建**作用域符号表**追踪 `import as` 别名、赋值别名、链式别名、元组解包、字典 / 列表下标取值、`dict.get/pop`、`getattr` 常量与动态两种形态、函数参数重绑定、内层函数遮蔽外层——都能追回最初的危险符号；**36 例单测逐类钉死绕过路径，同时保留 `os.path` 不误杀**。
- **沙箱六项约束 + 内存超限单独识别**：断网 / 根只读 / 代码与数据全只读挂载 / 唯一可写卷是会话输出目录 / 工作区 tmpfs 限 64MB / 1 核 256MB 30s；OOM 按 exit 137 与日志特征识别，不笼统报「执行失败」。
- **写操作靠框架硬停而不是自觉**：编译期声明 `interrupt_before=["approve"]`，审批节点前强制中断、状态落 SQLite 检查点（WAL）；人工确认后同 thread 续跑到原节点，前序步骤不重跑、进程重启不丢进度。
- **模型的沉默也是失败**：让它调工具它只回一段描述。把「未调用任何工具」写成一条结构化失败塞回结果逼其修正，连续两次则跳步收尾——**不是重试到上限**。
- **只读根会让无辜的写入也失败**：matplotlib 往 HOME 写字体缓存、往工作目录写临时文件，根只读后直接 OSError，报错与代码逻辑无关、模型会误判成自己写错。解法：执行前注入环境垫片（缓存与 `TMPDIR` 指到 tmpfs、强制 Agg、内置中文字体族、拦截 `makedirs` 只读异常）——**把「环境不适配」从模型要解决的问题里摘出去**。

### 项目三｜企业知识库问答：Agentic RAG（检索作为模型的工具）　`2024.10 – 2025.05`　企业交付

**技术栈**：TypeScript / PostgreSQL + pgvector / Elasticsearch / Neo4j / Redis / Mem0

**一句话**：企业文档入库后自动清洗、切块、建索引；员工提问时 Agent 自己决定查不查、查几次、要不要顺带查图谱，答案标注章节与行号。

- **Agentic 检索**：检索不预置在链路里，而是模型手里的两个工具——`search_knowledge`（混合召回）与 `query_graph`（实体关系）。**查不查、查几次、要不要查图谱，由模型按问题复杂度自己决定**；证据不足时按提示词如实告知，不硬编。
- **切分保留结构**：自写 Markdown AST 解析，按标题层级建 region，小于 200 token 的小节按层级合并，再自适应切到 1200 / 上限 2000 token；代码块超 100 行按空行切、仍超 50 行再均分，不按字硬切。每块带章节路径、起止行号、前后块指针与 5 类语义标签（正文 / 代码 / 表格 / 列表 / 提示块）。
- **两路融合用 RRF**：向量路给余弦相似度、关键词路给 ES `_score`，两者没有共同刻度，加权求和等于用两把尺子量同一根棍子。改按排名融合（K=30，每路取 20），双路命中累加 `1/(K+rank)` 并标记来源；单路异常降级为单路，不让整查失败。
- **权限下推 + 闭包注入**：可访问文档集合拼进 SQL 的 `IN` 与 ES 的 `terms`，**不是检索完再剔除**——后者会让越权内容先进上下文；该集合在创建工具时闭包注入，不出现在工具入参里，模型没有通道去改。
- **记忆分三层，写入要判定**：Redis 滑窗存本轮上下文、DB 最近 19 条兜底、超过 14 条触发摘要只留 6 条；长期记忆走 Mem0 双层（用户 / 会话），**写入前由分类器判定该不该记、记哪层**，不搞「什么都记」。

### 项目四｜企业集成平台：连接器层 + 计费履约层（Agent 工具层的前身）　`2021.04 – 2023.09`　企业交付

**技术栈**：Python / Flask / Django / MySQL / Redis / 消息队列 / pandas

**一句话**：无代码集成平台（iPaaS）——第三方应用以「连接器」接入、用户在画布上编排，平台同时解决「异构系统如何一致」与「哪些动作收费、怎么扣、扣完还能不能用」。

- **参数契约单一来源**：把动作抽象成参数契约（类型 / 必填 / 可选值 / 复合类型 / 多级动态级联），界面渲染、提交校验与执行取参读同一份定义，新增动作只写声明不写渲染代码；**339 个连接器**（327 含动作定义）以同一套契约接入。
- **能力自注册表**：连接器自注册凭据校验 / 连通性测试 / 字段映射 / 样例数据四类入口，替代「每个连接器各写一套」的复制粘贴——**没有统一注册入口，接入成本随数量线性上升**。
- **计费模型四层拆分**：指标字典 → 套餐模板 → 履约实例 → 账本流水；模板层（价格、额度）与实例层（已售出的包、已用掉的量）分离，**改价不动存量用户**。计费点收敛为 6 类（周期 / 费率 / 包次 / 包时 / 扣费字段 / 余额抵扣），一份模型同时表达「额度上限」与「并发限速」。
- **交易收敛为策略族**：开通 / 续费 / 升级各一个实现，统一 `validate → quote → fulfill` 契约，同一对象既报价又履约——**报价口径与结算共用一份规则，结构上让支付回调可反算对账**。升级的关键规则是「额度取新、已用取旧」，堵住「先刷光再升级」白拿额度的漏洞。
- **校验前置 + 三级降级**：业务侧零计费逻辑，动作执行前只调权限与余额两个接口；扣减按「资源包额度 → 按单价折现金余额 → 余额不足拒绝」降级，额度耗尽自动转按量付费、**不中断执行**；多包按指标聚合方式合并（`count/sum` 求和、`max` 取最大），额度型任一包可用即放行、速率型取最严。
- **失败不打断流程**：权限或额度不足时把动作入参降级成一条可读提示回给编排侧，不抛异常中断——**这是今天 Agent 工具层「tool error 转文本回给模型」的同一条原则，只是当年消费方是流程图**。
